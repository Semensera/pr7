# Практична робота № 7: Комплексне тестування та інженерний аудит якості веб-додатків

Веб-додаток «Каталог навчальних модулів» із моделюванням станів екрана (`Screen States`), трирівневою системою дизайн-токенів (`tokens.css`), захистом від XSS-вразливостей та модульними перевірками на базі `console.assert()`.

## 1. Чекліст функціонального та граничного тестування (Test Checklist)

| № п/п | Назва сценарію та вхідні дані | Очікуваний результат | Фактичний результат | Статус |

## 2. Аудит адаптивності та Chrome DevTools Lighthouse

### Перевірка адаптивності (Responsive Testing)
* **375 px (Mobile):** картки шикуються в 1 колонку, панель інструментів та форма адаптуються вертикально, горизонтальна смуга прокрутки відсутня.
* **768 px (Tablet):** картки відображаються у 2 колонки, елементи керування не перекривають один одного.
* **1440 px (Desktop):** контент центрований у контейнері `1120px`, картки формують сітку з 3–4 колонок.

### Результати Chrome DevTools Lighthouse (Navigation Mode)
* **Accessibility:** `100`
* **Best Practices:** `100`
* **SEO:** `100`

## 3. Модульні перевірки (Unit Assertions)
Модульні тести винесено в окремий файл `tests.js`, підключений з атрибутом `defer`. Під час завантаження сторінки функція `runUnitTests()` перевіряє чисті функції `validateInput()`, `isValidState()` та `filterModules()` за допомогою нативного методу `console.assert()`. Повідомлення `Assertion failed` у консолі браузера відсутні.
